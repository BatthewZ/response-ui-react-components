Rows that are done or decided. **Ids are never reused**; a row here keeps the number it was
filed under, because other rows and commit messages cite it. Nothing is deleted from this file —
a refutation or a declined decision is a result, and the reason this repo writes them down is
that one living only in a commit body is invisible to the next reader.

Anchors here are *not* maintained. A `fixed` row points at code that changed by definition, so
its line number and fingerprint record where the defect was, not where anything is now. Do not
re-anchor them; do not gate on them.

Open work is in [`LEDGER.md`](./LEDGER.md).

## How this record was built, and where it went wrong

Kept because the failures were expensive and are not obvious in advance.

Code defects surfaced while documenting the components. **Not doc issues** — those get
fixed in the doc. These are places where the *code* is wrong, misleading, or violates a
contract (accessibility, the contrast contract, ETHOS token rules, logic). Logged here
for later audit rather than fixed inline, so the documentation pass stays reversible and
one concern at a time.

**Provenance:** surfaced by the `gen-component-docs` workflow — author + adversarial
verifier agents. Confidence tags apply to `unaudited` rows only: `corroborated` = an
author and an independent verifier flagged it separately; `spot-checked` = confirmed by
hand against the source; `candidate` = single-source, unverified; `caveat` = a passing
guard disagrees, or the claim cannot be settled in this repo.

**What a row *is*** — its kind (accessibility, behaviour, consumer contract, ETHOS contract,
environment, repo health) and its harm (blocking, content-loss, exclusionary, portability,
contract-only, meta) — is defined in [`TAXONOMY.md`](./TAXONOMY.md), with the seam rules for the
cases that classify two ways. Neither axis is a column here, by the same rule that keeps cluster
membership out: the join is done at report time. `Sev` predates both axes and blends them.

**Reconciled 2026-07-25 against HEAD.** Three read-only sweeps re-verdicted every open row
in #1–#440 against source; their verdicts are written in above. What that means for

**~~Known gap in the oracle~~ — closed 2026-07-26.** `verify:bugs` used to only bounds-check
that an anchor's line number existed in its file; nothing checked that the line still held the
code the row describes. That reconcile moved **157** anchors rotted under intervening patches —
better than a third of the table — and no gate would have caught one. Every anchor now carries a
content fingerprint in the markdown link title, `(src/x.tsx#L12 "fp:1a2b3c4d")`, which renders as
a tooltip and stays out of the table. It hashes the anchored line **plus one line either side**,
each trimmed and internally whitespace-collapsed, so a reindent does not fire but a token change
does. A missing or malformed fingerprint is a violation, not a skip.

**Editing an anchor:** run `node scripts/bugs-ledger.mjs --reanchor`. Where the code merely
moved, it finds the stored fingerprint elsewhere in the file and slides the line number to match,
leaving the digest alone — that is the 157-row case, and it is fully automatic. Where the content
at the anchor actually *changed*, it restamps and prints the row under **RE-VERIFY BY HAND**:
those rows may now be describing different code, and only a reader can say whether the row's
sentence still holds. Do not run `--reanchor` to clear a red gate without reading that list.
The fingerprints were first stamped against `1ed1755`; a first stamping certifies today's
content and nothing more.
