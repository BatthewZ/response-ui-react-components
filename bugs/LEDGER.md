fixed in the doc. These are places where the *code* is wrong, misleading, or violates a
contract (accessibility, the contrast contract, ETHOS token rules, logic). Logged here
for later audit rather than fixed inline, so the documentation pass stays reversible and
one concern at a time.

verifier agents. Confidence tags apply to `unaudited` rows only: `corroborated` = an
author and an independent verifier flagged it separately; `spot-checked` = confirmed by
hand against the source; `candidate` = single-source, unverified; `caveat` = a passing
guard disagrees, or the claim cannot be settled in this repo.

### 441 · MultiSelect — a chip cannot be removed from the keyboard (med)

`MultiSelect.tsx:237` sets `tabIndex={-1}` on every chip's remove `<button>`. The only keyboard
route to removal is Backspace on an empty query (`:195-202`), which removes the **last** chip;
an arbitrary chip in the middle of the selection has no keyboard path at all. WCAG 2.1.1.

The sibling proves the fix is available and free: `TagInput.tsx:194-200` renders the same
control with no `tabIndex`, so its chips are tabbable. Removing the attribute makes each chip a
tab stop, which is the standard multiselect pattern; the alternative (arrow-key roving over the
chip row) is what `useRovingFocus` exists for.

Not a duplicate of the three MultiSelect chip rows already logged: #267 is focus loss *after* a
successful mouse removal, #268 is the glyph's contrast, #272 is duplicate React keys.

### 442 · VirtualizedDataTable — `onEndReached` deadlocks infinite loading (med)

```
const nearBottom = endIndex >= sortedData.length - endReachedThreshold;   // :182
if (nearBottom && sortedData.length > 0 && !firedRef.current) {           // :185
  firedRef.current = true; onEndReached();
} else if (!nearBottom) { firedRef.current = false; }                     // :189
```

The latch is re-armed only when the window leaves the threshold. A consumer appending a page
smaller than the window's overshoot past `len - threshold` never leaves it, so `nearBottom`
stays `true`, `firedRef.current` stays `true`, and the loader is never called again — the list
stops loading permanently with no error and no signal.

Measured: 20 rows, threshold default → 1 call. Consumer appends 4 rows → still 1 call.

#374 is the opposite end of the same effect (it fires before any scroll, including from the
`loading` branch, because the effect sits above both early returns). Fixing one does not fix the
other: #374 wants a guard on the *first* call, #442 wants the re-arm keyed to the data length
rather than to `nearBottom`.

2. `isCurrent` is `m === displayedMonth.getMonth()` — the month the grid is *showing*, not the
   month of the selected value. Where the attribute is honoured, quick-nav announces navigation
   state as selection, which is worse than dropping it.

Fix both together: the selection state belongs on the `role="gridcell"` wrapper (as #314
prescribes) and the flag should read the selected value, with the displayed month carried by
`aria-current` instead.
