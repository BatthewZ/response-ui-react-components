# Findings ledger

Open defects in this package's shipped code, one row per finding. **This file is the work
list**: everything in it is believed true at source and unfixed. Closed rows live in
[`ARCHIVE.md`](./ARCHIVE.md); findings about the audit itself — gates, tests, the record —
live in [`AUDIT.md`](./AUDIT.md). Arriving cold? Start with [`HANDOVER.md`](./HANDOVER.md).

- **What a row *is*** — its kind and its harm — is defined in [`TAXONOMY.md`](./TAXONOMY.md).
  Work order is **harm first**: blocking, then content-loss, then exclusionary, then
  portability, then contract-only.
- **Work order is harm**, per [`TAXONOMY.md`](./TAXONOMY.md). ([`PLAN.md`](./PLAN.md) is retired — it survives only as a section map for the archived rows that cite it.)
- **Verify before you fix.** A row is a claim, not a fact. This file has carried a row marked
  `confirmed · high` whose sentence was false at source, and seven claims that measurement
  disproved. Read the code before you change it; if the row is wrong, say so in the row.
- **Enumerate, never count.** A row saying "three components" that does not name them cannot be
  audited, and one such row hid the same defect in three further components for a whole pass.
- **Same-root siblings are not duplicates.** Rows sharing a cause in different components have
  different anchors and sometimes different fixing commits. Merging them destroys a reference.
- **One instance fixed is not a row closed.** A row naming two components needs both.
- `deferred` means an owner declined it, with the reason in the status. Those rows are open on
  purpose; re-deciding needs the owner, not a re-measurement.

Line numbers in anchors drift as code moves. `node scripts/bugs-ledger.mjs --reanchor` slides
them back when the code merely moved, and prints the rows where the content actually changed —
those may now describe different code, and only a reader can say.
