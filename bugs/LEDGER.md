# Findings ledger

Open defects in this package's shipped code, one row per finding. **This file is the work
list**: everything in it is believed true at source and unfixed. Closed rows live in
[`ARCHIVE.md`](./ARCHIVE.md); findings about the audit itself — gates, tests, the record —
live in [`AUDIT.md`](./AUDIT.md).

- **What a row *is*** — its kind and its harm — is defined in [`TAXONOMY.md`](./TAXONOMY.md).
  Work order is **harm first**: blocking, then content-loss, then exclusionary, then
  portability, then contract-only.
- **How rows group into fixes** is [`PLAN.md`](./PLAN.md).
- **Verify before you fix.** A row is a claim, not a fact. This file has carried a row marked
  `confirmed · high` whose sentence was false at source, and seven claims that measurement
  disproved. Read the code before you change it; if the row is wrong, say so in the row.
- **Enumerate, never count.** A row saying "three components" that does not name them cannot be
  audited, and one such row hid the same defect in three further components for a whole pass.
- **Same-root siblings are not duplicates.** Rows sharing a cause in different components have
  different anchors and sometimes different fixing commits. Merging them destroys a reference.
- **One instance fixed is not a row closed.** A row naming two components needs both.
- `deferred` means an owner declined it, with the reason in the status. Those rows are open on
  purpose; re-deciding needs the owner, not a re-measurement.

Line numbers in anchors drift as code moves. `node scripts/bugs-ledger.mjs --reanchor` slides
them back when the code merely moved, and prints the rows where the content actually changed —
those may now describe different code, and only a reader can say.

### 127 · Popover · HoverCard · DropdownMenu — a dangling `aria-controls` on three floating triggers (low → med)

Re-scoped from `low` and from "harmless today". The mechanism the row named is real, but the
consequence it dismissed is a live WCAG 4.1.2 failure.

`useRole` is re-exported bare from `@floating-ui/react` (`src/hooks/use-floating.ts:51`) and
supplies its own floating `id`. Three components set their own `id` *above* the spread that
carries floating-ui's, so floating-ui's wins and the panel never carries the id its trigger
advertises:

| trigger advertises | panel sets `id` at | spread that overwrites it |
| ------------------ | ------------------ | ------------------------- |
| `Popover.tsx:149` | `Popover.tsx:196` | `:199` |
| `HoverCard.tsx:139` | `HoverCard.tsx:185` | `:192` |
| `DropdownMenu.tsx:73` | `menu-internals.tsx:182` | `:185` |

### 441 · MultiSelect — a chip cannot be removed from the keyboard (med)

`MultiSelect.tsx:237` sets `tabIndex={-1}` on every chip's remove `<button>`. The only keyboard
route to removal is Backspace on an empty query (`:195-202`), which removes the **last** chip;
an arbitrary chip in the middle of the selection has no keyboard path at all. WCAG 2.1.1.

The sibling proves the fix is available and free: `TagInput.tsx:194-200` renders the same
control with no `tabIndex`, so its chips are tabbable. Removing the attribute makes each chip a
tab stop, which is the standard multiselect pattern; the alternative (arrow-key roving over the
chip row) is what `useRovingFocus` exists for.

Not a duplicate of the three MultiSelect chip rows already logged: #267 is focus loss *after* a
successful mouse removal, #268 is the glyph's contrast, #272 is duplicate React keys.

### 442 · VirtualizedDataTable — `onEndReached` deadlocks infinite loading (med)

```
const nearBottom = endIndex >= sortedData.length - endReachedThreshold;   // :182
if (nearBottom && sortedData.length > 0 && !firedRef.current) {           // :185
  firedRef.current = true; onEndReached();
} else if (!nearBottom) { firedRef.current = false; }                     // :189
```

The latch is re-armed only when the window leaves the threshold. A consumer appending a page
smaller than the window's overshoot past `len - threshold` never leaves it, so `nearBottom`
stays `true`, `firedRef.current` stays `true`, and the loader is never called again — the list
stops loading permanently with no error and no signal.

Measured: 20 rows, threshold default → 1 call. Consumer appends 4 rows → still 1 call.

#374 is the opposite end of the same effect (it fires before any scroll, including from the
`loading` branch, because the effect sits above both early returns). Fixing one does not fix the
other: #374 wants a guard on the *first* call, #442 wants the re-arm keyed to the data length
rather than to `nearBottom`.

### 452 · CalendarBase — quick-nav marks the *displayed* month as selected (med)

`CalendarBase.tsx:317` and `:346` write `aria-selected={isCurrent}` on plain `<button>`s in the
month and year quick-nav grids. Two defects at once:

1. `aria-selected` is not supported on role `button`, so a conforming AT drops it — the same

2. `isCurrent` is `m === displayedMonth.getMonth()` — the month the grid is *showing*, not the

prescribes) and the flag should read the selected value, with the displayed month carried by
`aria-current` instead.
